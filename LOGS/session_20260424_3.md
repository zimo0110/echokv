### 2. `core/canary_estimator.py` — full real implementation

Replaced the session-1 stub with a complete, thread-safe implementation:

* `reset()` — zeros all per-layer EMA state and clears scratchpads.
* `observe(layer_id, step, kl, *, is_canary)` — strict no-op when
  `is_canary=False` (INV-4); when `True`, updates the EMA (cold-start
  seeds directly rather than blending from zero) and appends a
  `CanarySample` to the per-layer scratchpad ring.
* `ema(layer_id)` — returns δ̂_ℓ (the PID controller's read path).
* `snapshot()` — returns a copy of the full EMA vector; the caller
  gets its own list (mutation-safe).
* `scratchpad_samples(layer_id)` — returns a copy of raw samples for
  offline analysis.
* `is_canary_step(rng)` — Bernoulli(p_c) draw. Accepts an optional
  `random.Random` for deterministic unit tests.
* `threading.Lock` serialises `observe()` and `ema()` / `snapshot()`
  across threads. Lock is never held across a kernel call.

EMA update: `δ̂ = (1-α)·δ̂_prev + α·δ` (α=0.1 default). Cold start
seeds the EMA at the first observed value to avoid a fictitiously low
initial estimate during the controller's warm-up window.

### 4. `kernels/canary_attention.py` — dense reference + paged stub

**Redesign note (important for future implementors):** the dense
reference measures the same δ as the motivation study:

  ȧ_ℓ = attention(Q, dequant(quant(K_fp16)))  — simulated INT{b} path
  ā_ℓ = attention(Q, K_fp16)                   — FP16 reference

This is NOT the same as the production paged kernel's signal, which
will measure:

  ȧ_ℓ = FlashInfer's INT4 paged attention output
  ā_ℓ = attention(Q, explicit_dequant(K_stored))

The motivation study showed the first quantity correlates with
accuracy. The production system uses the second as an online proxy.
Both capture INT4 precision loss; the dense reference is the testable
oracle for the production kernel's correctness.

Implemented:
* `CanaryScratchpad` — plain Python list, test-friendly. Production
  path will use a pinned CUDA ring buffer.
* `dense_canary_attention(q, k, v, ...)` — takes FP16 Q/K/V. On the
  canary path: quantizes K internally (via `simulate_quantization`),
  computes both ȧ and ā, writes δ = mean KL(ȧ ‖ ā) to the scratchpad.
  Non-canary path: standard attention, no side effects.
* `canary_paged_attention(...)` — production stub; raises
  `NotImplementedError` until FlashInfer is installed. The INV-4
  `xfail` is the acceptance test.

**Bugs encountered and fixed during kernel redesign:**

1. **Wrong stream-0 K values.** First draft passed raw integer K (0–15
   for INT4, 0–3 for INT2) to `_attention_weights` for stream 0 instead
   of the dequantized values. This caused INT2 KL < INT4 KL (reversed
   ordering). Fix: have the dense reference take FP16 K as input and
   quantize/dequantize internally, matching the motivation study.

2. **Negative `group_axis` in manually constructed `QuantizedTensor`.**
   The `kivi.dequantize` function does not normalize `group_axis`, so
   `group_axis=-1` with a 4D tensor makes `shape[axis+1:]` = `shape[0:]`
   (full shape). The `quantize` function normalizes and stores the
   positive axis; the tests that manually constructed `QuantizedTensor`
   were passing `-1`. Fix: don't reconstruct `QuantizedTensor` manually
   in tests — let `quantize()` return it directly and pass the
   `QuantizedTensor` through. This is documented in test comments.

## Decisions made this session

1. **Dense reference measures motivation-study δ, not production δ.**
   The two differ: the dense reference can access the original FP16 K
   (since it's the oracle, not the production path), so it computes
   the cleaner signal. The production paged kernel will measure the
   runtime δ from stored INT4 blocks. Both signals correlate with
   precision loss; the dense reference is the right oracle for
   correctness testing. Recorded above.

2. **EMA cold-start seeding.** First observation seeds δ̂ at its
   value rather than blending from zero (which would give a
   fictitiously low initial estimate during warm-up, delaying the
   controller's first real response). The reset path also re-enables
   cold-start. Verified by test.

3. **CanaryScratchpad as a plain Python list.** The production path
   needs a pinned CUDA ring buffer (zero-copy GPU→CPU). The plain
   Python list is the testable stand-in; production implementation
   replaces it with a pinned buffer once the Triton kernel lands.
