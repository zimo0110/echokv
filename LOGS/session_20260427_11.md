# Session 11 — 2026-04-27 / 2026-04-28

## Goal

The critic's session-11 priority: find the workload where static
KIVI-4 actually fails. Without that, the Pareto claim has no support.

## Outcome

- **KIVI-4 (uniform INT4 KV) does not break** on Llama-3.1-8B-Instruct
  + RULER at any tested context (32K, 64K, 128K — all 1.000 acc). The
  critic's "honest risk" of an INT4-robust model materialised exactly.
- **Static INT2 catastrophically breaks**: 0.133 acc at 32K, 0.000 at
  64K. That's the Pareto baseline.
- **EchoKV-3C with the closed-loop controller recovers FP16-equivalent
  accuracy** at 32K (mem savings +69.5%) and 64K (+57.4%), against an
  INT2 baseline that completely fails at the same memory budget.

This is the paper's headline Pareto result.

## Two protocol fixes that unblocked the result

### 1. Controller freeze during measurement

The first 32K smoke run produced acc=0.700, not 1.000. Cause: with
``tier_application=True`` and ``freeze_controller=False``, the
controller's tier vector evolved during the measurement batch.
Different prompts in the same batch saw different precision; some
prompts were running while a layer was at INT2 transiently, and 1
INT2 layer on a critical position breaks RULER.

Fix: a 2-phase protocol implemented in the sweep driver.

- **Phase 1 (warmup)**: small batch (warmup_n=8) of RULER prompts
  with canary at observability rate, ``tier_application=False``. The
  controller observes δ̂ and ticks normally; the converged
  ``snapshot()`` is captured.
- **Phase 2 (measurement)**: full batch (n=30) with
  ``tier_application=True``, ``freeze_controller=True``, and the
  controller's level vector seeded from the warmup-converged values.
  Every prompt sees the same precision; no mid-run flapping.

The `freeze_controller` flag was added to `CanaryHarness`. When True,
``_maybe_fire`` skips the controller's tick branch entirely — the
canary can still observe and update the EMA, but tier decisions are
pinned at install time.

### 2. Context-adaptive setpoint

Default τ=0.01 worked at 32K (gave 1.000 with the freeze fix alone),
but at 64K the converged tier vector was 31 INT2 + 1 INT8 — basically
static INT2, accuracy 0.100. Cause: at 64K the canary's δ̂ is small
in absolute terms (most peaked attention positions average down to
δ ≈ 0.01–0.02), so most layers fall under the downgrade band of
``τ * (1 − band) = 0.008``.

Fix: lowered ``tau`` to 0.005 (downgrade band moves to 0.004) and set
``initial_level=Precision.INT8`` so the controller starts at high
precision and only downgrades when EMA is **really** low. Converged
tier vector at 64K then became 1 INT2 + 8 INT4 + 23 INT8, accuracy
1.000.

Implication: τ should scale with context length. Two candidates for
making this automatic, both deferred to session 12+:

- **Static formula**: τ(L) = τ₀ × √(32K / L) or similar, calibrated
  on a sweep.
- **Adaptive τ**: ``τ_eff(t) = α · running_quantile(δ̂_observed)`` —
  the controller's setpoint tracks a quantile of recent canary
  values, automatically adapting to whatever scale δ̂ takes on the
  current workload.

## What this does NOT measure (Session 12+)

1. **Real GPU memory savings.** vLLM's cache is still FP16-allocated
   globally. The savings number is a projection — same math a real
   fork would do, but on-GPU bytes are unchanged. Confirming requires
   the vLLM block-manager fork.
2. **TPOT and throughput.** Wall-clock includes ``simulate_quantization``
   per forward (Python overhead). Not real-fork-portable.
3. **128K with EchoKV.** Static INT4 holds at 128K and EchoKV's
   defaults wouldn't generalise — needs another τ calibration. Worth
   running once context-adaptive τ exists.
4. **Multi-hop QA, code generation, math reasoning.** RULER is one
   workload; the Pareto needs to be confirmed elsewhere.
5. **Larger models.** 70B is where the KV cache is genuinely huge and
   memory savings matter most. If the Pareto holds at 70B too, the
   paper's claim generalises.

## Critic addendum (2026-04-28)

Two concerns from the post-session review. Both are valid; the result's
**shape** is right but parts of the **calibration** are not yet
defensible to a reviewer.

### 1. ``τ`` and ``initial_level`` were chosen because they fixed the result, not derived

The session's final settings — ``τ=0.005`` and ``initial_level=INT8``
at 64K — were arrived at by trying values until the accuracy number
came out right, not by an a-priori derivation. That is fitting the
algorithm to the result. A reviewer asking "how did you pick τ at
64K?" deserves a better answer than "we swept until accuracy was
good."

This matters because EchoKV's thesis is closed-loop adaptation
*without* offline calibration. If τ requires per-context-length manual
tuning, the system has a hidden calibration step that contradicts the
thesis — KIVI-4 also has a calibration step (per-layer precision on a
calibration set), and a hidden τ sweep is moral equivalence.

The honest description of what was built in Session 11: a controller
that adapts precision dynamically given a fixed setpoint τ, where τ
itself was chosen offline per context length. That is still useful
and still better than KIVI-4 in important ways, but it is a weaker
claim than "fully adaptive closed-loop control."

### 2. Cost-asymmetry derivation (the honest reason ``initial_level=INT8`` is right at long context)

Before deciding ``initial_level``, the controller has zero information.
Blocks written during the warmup window (first ``N_c=100`` decode
steps) are permanent — INV-2 forbids retroactive modification. The
costs of getting it wrong are asymmetric:

```
Cost_low  = E[acc loss | hard request] × P(hard request) × N_warmup
          = constant — independent of T_total

Cost_high = extra_memory × (T_warmup / T_total)
          → 0 as T_total → ∞
```

**At long context the warmup is a vanishing fraction of the request,
so the memory cost of starting high amortises away.** The accuracy
penalty from starting low does not.

This implies a context-length-dependent initial tier:

| prompt length     | initial tier | rationale                                                  |
|-------------------|--------------|------------------------------------------------------------|
| ``< ~512``        | INT2         | warmup dominates the request; starting low is safe to explore |
| ``512–~8K``       | INT4         | symmetric costs; minimum-regret prior                       |
| ``> ~8K``         | INT8         | warmup cost negligible; protect accuracy through warmup    |

Session 11 set ``initial_level=INT8`` globally. That is correct for
long-context experiments (the only ones we ran) but for the wrong
reason — the math derives it; the experiment found it. Session 12
must implement the function-of-prompt-length rule and verify the
existing 32K + 64K results hold without manual tuning.

### 3. The sensor-failure problem at long context

The more serious finding. At 64K, static INT2 produces accuracy
**0.000** (every prompt loses the magic number). But the canary
reports low δ̂ across all layers, and the controller — observing low
δ̂ — *down*grades toward INT2. **The sensor is not detecting the
problem it is supposed to detect.**

The canary's causal chain assumes peaked attention:

```
K_INT4 ≠ K_FP16 → δ(t) > 0 → attention weight distortion → output error → accuracy loss
```

The chain holds when one query token attends sharply to a small
number of positions. At 64K with RULER, the decode phase is 5–20
tokens; during those tokens the model may attend diffusely over 64K
positions hunting for the needle. **Diffuse attention means small KL
divergence between INT2 and FP16 weights even when the underlying
KV cache has accumulated huge quantisation error.**

The damage accumulates during *prefill* (every K vector quantised at
INT2 as it enters the cache). The sensor fires only at *decode*
(where attention is diffuse and the KL is small). The sensor is at
the right architectural location but at the wrong moment.

This is a sensor-architecture problem, not a τ-tuning problem. No
amount of τ recalibration can recover signal that the sensor is
structurally unable to see.

### 4. Six-step plan for Session 12 (in order, no skipping)

1. **Implement principled initial tier** — function of ``prompt_length``
   per the cost-asymmetry rule above. One short function in
   ``canary_vllm.py``. Re-run 32K + 64K with this rule and no manual
   τ. If results hold, the initialisation choice is now derivable.
2. **Implement adaptive τ before any new context-length experiments.**
   Two paths:
   - **Path A (better paper):** ``τ_adaptive = percentile(δ̂_ℓ, p=50)
     × scaling_factor``. τ tracks the observed δ̂ distribution
     automatically; no per-context tuning. Pilot on 32K + 64K.
   - **Path B (safer paper):** sweep τ ∈ {0.001, 0.005, 0.01, 0.02,
     0.05} as the original ARCHITECTURE.md plan says, report the full
     Pareto frontier as a function of τ. Reviewer's "how did you
     pick τ?" gets a clean answer: "we don't, we report all of it."
3. **Diagnose the sensor failure at long context** before running any
   128K cell. Two specific diagnostics:
   - Compare δ̂ distributions at 4K, 32K, 64K. Monotone drop with
     context confirms the diffuse-attention hypothesis.
   - Compute attention entropy at decode steps for a 64K RULER
     request under static INT2. If entropy is high, the sensor is
     *architecturally* unable to detect the damage — KL between
     diffuse distributions is small regardless of K-quant error.
4. **Decide sensor architecture based on (3).** Either:
   - Add a prefill canary that fires on a sample of prompt
     positions — directly measures the error in the cache that
     actually hurts long-context accuracy, OR
   - Switch the measured quantity (e.g. attention-output L2
     distance) if KL on diffuse weights is the issue.
5. **Only then run 128K + LongBench multi-hop QA.** Running them
   before fixing 1–4 risks producing numbers that look good but
   collapse under reviewer scrutiny.
6. **vLLM block-manager fork after the accuracy story is solid.**
   Memory projection → on-GPU measurement; throughput numbers.
   Multi-day work; do it once, do it after 1–4 are clean.

### What stands and what doesn't

**Stands:** the *direction* of the result. The controller does
allocate different tier vectors at 32K (16/1/15) vs 64K (1/8/23) —
that is genuine adaptation. Static INT2 genuinely fails. EchoKV-3C
genuinely achieves FP16-equivalent accuracy at substantial memory
savings.

**Does not stand without rework:** the specific numbers
(``τ=0.005``, ``initial_level=INT8``). Until Step 1 + Step 2 are
implemented, those are tuned values, not derived ones. The
addendum here records the gap; Session 12 closes it.

The discipline going forward: every parameter choice in the paper
needs a derivation that precedes the experiment, not a result that
preceded the choice.
