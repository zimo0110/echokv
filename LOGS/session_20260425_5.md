## Diagnosis

### What worked

The chat template fix (session 4) fully resolved the GSM8K truncation
problem:
- v3: acc=0.010, σ=0.099, all 400 completions hit max_new_tokens=256
- v4: acc=0.810, σ=0.392, completions average ~150 tokens, 0 truncated
- σ=0.392 is well above the 0.10 threshold — variance is adequate

### Root cause of FAIL: wrong correlation target

The gate correlates δ (KL divergence of attention weights, computed on
a FP16 forward pass) against FP16 accuracy. These quantities are
independent by construction:

- δ measures: "how much would the attention weights change if K were
  quantized to INT4?" — a theoretical sensitivity metric from one FP16 run.
- FP16 accuracy measures: "does the model solve this problem with full
  precision?" — driven by problem difficulty, not quantization sensitivity.

A problem that is difficult (low FP16 accuracy) need not have high δ, and
vice versa. The two quantities measure orthogonal properties.

To get a meaningful correlation the target must be:
  Δacc = acc_FP16 − acc_INT4 (accuracy degradation under INT4 KV cache)

This requires running each request twice:
1. FP16 KV cache → acc_FP16
2. INT4 KV cache → acc_INT4 (requires actual INT4 KV inference)

The current harness only implements the FP16 path + theoretical δ.

### Other workload outcomes

**RULER-32K**: acc=1.0, σ=0.0 — confirmed ceiling at 8K (same as v3).
Model retrieves single needle 100% under INT4 at 8K. Unchanged outcome.

**HumanEval**: n=0 — all 164 `score_fn` calls return `float('nan')` by
design (no sandbox executor). The analyze module filters NaN scores,
leaving n=0 → `insufficient`. Not a gate blocker once INT4 accuracy is
measured (HumanEval code generation quality does degrade under INT4).

## Decisions

1. **Gate redesign required before v5.** The gate must correlate δ against
   Δacc = acc_FP16 − acc_INT4. This requires INT4 KV inference per request.

2. **Alternative gate signal: attention entropy / per-head kurtosis.** The
   analyze.py pivot recommendation. Potentially computable from the FP16
   forward pass without INT4 inference. To be explored in next session.

3. **Canary kernel blocked on gate redesign.** INV-4 xfail unchanged.
