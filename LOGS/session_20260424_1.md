## Goal

Bootstrap the EchoKV repository: project documentation, source-tree
skeleton, the precision-aware block allocator (real implementation),
typed interface stubs for every other core module, and the invariant
tests (INV-1..INV-5) as runnable pytest tests.

## Research context in force at session start

* Thesis: KV quantization error is a runtime property of the current
  conversation, not a static property of the model.
* Three-component core (ships regardless): Shadow Canary + PID
  Controller + SLO Budget.
* Fourth component (Path B / Write-Ahead Precision): experimental,
  ablation-gated. Ships iff RULER@128K improves by ≥0.5pt over the
  three-component system at ≤15% memory overhead.
* Information-theoretic axiom: retroactive INT4→INT8 re-quantization
  is vacuous. Any retroactive repair requires an FP8 shadow (≥50%
  memory overhead) and contradicts the memory-reduction motivation.
  Therefore: no shadow buffer, no retroactive repair, no page
  refresh worker — the canary uses existing KIVI per-group scales.
* Single-node TP scope (≤8 GPUs, NVLink). Multi-node TP is
  explicitly out of scope for MLSys 2026.

## Decisions made and rationale

1. **`OutOfMemory` is raised rather than auto-downgraded.** The
   controller owns precision policy; the allocator is mechanism.
   Silent downgrade would let the allocator make a policy choice
   that should involve the canary signal and the budget.
2. **Pool sizes fixed at construction time.** Adaptive resizing
   risks thrashing; deferred. Recorded under REPORT.md § Open
   Questions.
3. **INV-1 text scan uses identifier-form patterns only.** A
   docstring that *denies* the existence of an FP8 shadow (i.e.
   explains why we don't have one) is valuable architectural
   commentary. Forbidding the prose would push authors to delete
   the "why not" rationale. The scan only catches actual
   identifiers (snake_case or CamelCase).
4. **Allocator includes `incref`.** vLLM supports copy-on-write
   / prefix sharing; reference counting is the minimum
   integration surface we need even at the reference-impl stage.
5. **`tests/test_invariants.py` is runnable *now*, with strict
   xfails for un-implementable parts.** A test that's "commented
   out until later" is a test that gets forgotten. `xfail(strict=True)`
   flips to a failure if the test starts passing accidentally — a
   tripwire for unexpected changes.

   we need evidence that δ(ℓ,r) correlates with task accuracy
   (Spearman ρ ≥ 0.5). If the signal isn't there, the architecture
   is moot. Deliverables: violin plot, layer heatmap, Spearman ρ.
2. Pin vLLM and FlashInfer commits in CHANGELOG.md.
3. If the motivation study succeeds: begin the Triton canary
   kernel. The INV-4 xfail is the acceptance test.
4. If the motivation study fails (ρ < 0.5): evaluate attention
   entropy and per-head kurtosis before any further system work.
