## Tasks

### TASK 1 — PID precision controller (`core/precision_controller.py`)

Replaced the interface-only stub with a real implementation. Per
ARCHITECTURE.md § 4.2:

- **Per-layer hysteresis ladder** over (INT2, INT4, INT8). On each
  tick:
  - if `δ̂ > τ_eff`: upgrade one tier (capped at INT8)
  - elif `δ̂ < τ_eff · (1 − H)`: downgrade one tier (floored at INT2)
  - else: hold
- **Effective setpoint:**
  ```
  τ_eff(u, b) = τ · (1 + 1.5·u + 1.5·(1 − b))
  ```
  Monotone non-decreasing in `u` (relax under utilisation pressure),
  monotone non-increasing in `b` (tight budget → high τ_eff → harder
  to upgrade → save memory). `g(0, 1) = 1` baseline; `g(1, 0) = 4` at
  worst-case pressure.
- **Stall counter** (`min_dwell_ticks`) — after a transition a layer
  holds for ≥ N ticks before the next transition is allowed. Prevents
  pathological flap when δ̂ wobbles just outside the deadband.
- **Decisions** — `tick()` returns one `PrecisionDecision` per layer
  (previous, target, direction, tick). The scheduler is responsible
  for broadcasting them via the SLO budget; this module only emits
  intent (INV-3 stays out of the controller).

### TASK 2 — SLO budget (`core/slo_budget.py`)

Replaced the stub with a rolling-window TPOT tracker:

- `update_tpot_sample(tpot_ms)` appends to a `deque(maxlen=window)` of
  raw TPOT samples; recomputes p99 from the window and maps to a
  budget.
- `update_p99(p99_tpot_ms)` accepts a pre-computed p99 (for callers
  that already maintain their own latency stats; vLLM metrics).
- Mapping: `ratio = p99 / target`; budget = `max_budget` at
  `ratio ≤ 1`, `min_budget` at `ratio ≥ 2`, linear interpolation in
  between. Monotone non-increasing in ratio so SLO pressure tightens
  the budget.
- `register_broadcast_callback(cb)` + `broadcast_precision(levels,
  tp_world_size)` — the INV-3 enforcement point. Callback runs
  synchronously in the caller's thread before `broadcast_precision`
  returns; every call increments `num_broadcasts` for audit.

### TASK 4 — INV-3 flip

`tests/test_invariants.py::test_inv3_slo_budget_broadcast_is_synchronous`
rewritten from the placeholder (which was strict-xfail, called
`broadcast_precision` on the stub, and expected `NotImplementedError`)
into a real mock-scheduler harness:

- A `scheduler_cb(levels, tp_world_size)` records the level vector +
  the decode-step counter at the time of the callback.
- Three broadcasts simulate three controller ticks; between each
  broadcast an `admit_next_decode_step()` increments the counter.
- Asserts: (a) every emit fired exactly one synchronous broadcast;
  (b) callback observed the exact levels + tp_world_size; (c) the
  decode-step counter at broadcast `i` is strictly less than at
  broadcast `i+1` — broadcasts precede the admission of the next
  decode step.

Strict-xfail removed. Test now passes by exercising the actual contract.

## Decisions / things worth recording

1. **`min_dwell_ticks = 2` default.** Hysteresis band alone prevents
   simple oscillation, but doesn't prevent the case where δ̂ legitimately
   drifts across the band over consecutive ticks. The stall counter
   guarantees a minimum dwell at every level. 2 ticks @ N_c=100 = 200
   decode steps minimum dwell, which is well below any meaningful
   conversation-state change.
2. **Initial decisions allowed on tick 1.** `_last_change_tick` is
   seeded to `-(min_dwell_ticks + 1)` so the dwell check passes on the
   first tick — the controller can immediately move out of INT4 if
   the cold-start signal is already strong. Without this seeding,
   layers would be stuck at INT4 for the first `min_dwell_ticks`
   ticks regardless of evidence.
3. **Budget mapping is intentionally piecewise-linear.** Sweepable in
   ablation (paper Table 4 / Open Question on PID coefficients) and
   monotone — the only properties the controller actually relies on.
4. **`broadcast_precision` increments `num_broadcasts` even when no
   callback is registered.** Lets controller-only unit tests audit
   broadcast cadence without a real scheduler in the loop.
5. **The end-to-end test runs at `canary_rate = 1/4`** for speed. The
   production rate is `1/64`; the controller code path is identical,
   just fires less often. The test exercises the same wiring.
6. **Layer indices from v8.1 are NOT hard-coded in production code.**
   The end-to-end test reads `HIGH_SIGNAL_LAYERS = {21, ..., 27}`
   from the test file only and uses it to *generate* the synthetic δ.
   The controller never sees this set; it discovers the structure
   from EMA δ̂_ℓ. This is the closed-loop premise enforced as a test.

vLLM scheduler integration:

1. **Wire `SLOBudget.broadcast_precision` into vLLM's scheduler-step
   barrier.** vLLM V1's scheduler runs a step loop; the broadcast
   callback fires from inside that loop, before any rank advances. The
   adapter layer reads `controller.snapshot()` after the controller
   tick, calls `budget.broadcast_precision(snapshot, tp_world_size)`,
   and the registered callback updates each rank's view.
2. **Wire `CanaryEstimator.observe` into the FlashInfer canary kernel
   call site.** The canary kernel currently takes an `estimator` kwarg
   directly; in vLLM the call site is the per-layer paged attention
   call inside the model executor. Expose the estimator on the model
   instance.
3. **First Llama-3.1-8B inference run with the full system active.**
   Measure end-to-end TPOT with and without the canary path active;
   target is <2% overhead at `p_c = 1/64`. This is where the
   theoretical claim turns into measurement. ARCHITECTURE.md § 4.1 +
   the overhead table in REPORT.md get filled in.
4. **PI/PID extension** — currently P-only. If the scheduler ablation
   shows sustained tracking error (mean δ̂ stays consistently above
   τ_eff for many ticks on a stable workload), add an integral term.
   Open question in REPORT.md.
5. **Multi-conversation interference test.** When two conversations
   with different δ profiles share the GPU, the per-layer level
   vector applies to *new allocations only* (INV-2); a heavy
   conversation arriving mid-stream upgrades subsequent blocks but
   doesn't disturb in-flight blocks. Worth pinning as an integration
   test before the vLLM harness lands.

## Critic-driven addendum (same session)

Four hardening fixes after review of the falsifiable layer-21–27 test:

1. **Margin calculation in the docstring.** Spelled out: 10 controller
   ticks at ``N_c=100``, ≥3 ticks per transition (1 decide + 2 dwell),
   2 transitions per layer to cap, 6 ticks consumed, 4 ticks margin.
   SNR breakdown for both high and low signal documented (3σ stays on
   the correct side of the relevant threshold). Future readers
   changing any of these knobs know the convergence budget.

2. **Per-layer-independent canary firing.** Production fires the
   canary per (step, layer) pair independently; the original test
   fired all 32 layers at once on selected steps. Replaced with a
   per-layer Bernoulli(p_c) draw via the new helper
   `_run_layer_discovery`. EMA still recovers the right mean; the
   test now exercises the independence the production system relies
   on.

3. **Slow variant at production canary rate.** Added
   `test_controller_discovers_high_signal_layers_at_production_rate`,
   marked `@pytest.mark.slow`. `canary_rate = 1/64`,
   `n_steps = 10 000`. Confirms the same convergence claim at
   realistic sampling density. Passes in ~1.1 s. `conftest.py`
   extended to register `slow` and skip-by-default; opt-in with
   `pytest -m slow`.

4. **Deadband-boundary oscillation test.** New
   `test_controller_no_flap_at_deadband_boundary` injects raw
   observations centred on the upper threshold (0.01 ± σ=0.001) so
   ~50% of samples land above, ~50% below. EMA + 20% deadband +
   `min_dwell_ticks=2` must hold transitions ≤ 1 over 50 ticks per
   layer. The harder oscillation case the critic flagged — the
   previous test only covered fully-in-band noise.
